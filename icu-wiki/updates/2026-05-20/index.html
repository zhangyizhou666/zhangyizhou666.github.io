Answer-Level Retriever Ablation

ICU Bench 30 was rerun through five cumulative retriever variants with fixed Gemma 4 E4B generation and DeepSeek V4 Pro judging.

retrieverablationgenerationdiagnostics

Purpose

This update reports an answer-level retriever ablation.

The experiment keeps the benchmark, generator, prompt, evidence count, and judge fixed. Only the retriever variant changes. The conservative production policy guard was bypassed for this diagnostic so that the result measures how each retriever version affects the generated answer, not how often the production guard refuses to answer.

The tested ladder is:

  • R0_basic_hybrid: PostgreSQL lexical FTS plus dense BGE-M3/pgvector retrieval.
  • R1_japanese_fts: R0 plus Japanese-tokenized FTS.
  • R2_metadata_exact: R1 plus entity alias lookup and title/heading matching.
  • R3_reranker: R2 plus BGE reranking over a larger candidate pool.
  • R4_full_current: R3 plus source-authority scoring.

The run used ICU Bench 30, generated 150 answers, and judged all answers with DeepSeek V4 Pro. The fixed generator was google/gemma-4-E4B-it.

Main result

The strongest improvement appears at R3_reranker. Average human quality rises from the 0.74-0.76 range to 0.8042, and blocking cases drop from 9-10 to 4.

R4_full_current is the best version in this run. It reaches 0.8333 average human quality, 0.4333 clean pass rate, and only 3 blocking cases.

The earlier modules do not monotonically improve the aggregate answer score by themselves. R1_japanese_fts and R2_metadata_exact are still useful system components, but their aggregate answer-level value is not visible until reranking and full source-aware scoring are included.

Evidence quality

Gold-source recall and MRR show the same overall trend as answer quality. The full current retriever has the highest gold-source recall and MRR:

  • R0_basic_hybrid: gold-source recall 0.3550, MRR 0.4494.
  • R3_reranker: gold-source recall 0.5144, MRR 0.5483.
  • R4_full_current: gold-source recall 0.6189, MRR 0.6105.

This supports the claim that the current retriever is not just changing the source mix; it is more often bringing GPT Pro gold evidence into the Top-5 context.

Failure tags

The main failure modes remain retrieval_miss, evidence_insufficient, and missing_key_condition.

Reranking reduces retrieval-miss-style blocking failures, but it does not eliminate missing-condition failures. In the full current retriever, the remaining failures shift more toward missing key conditions and evidence sufficiency rather than pure retrieval misses.

Question-level view

The question-level heatmap shows that the current retriever improves many cases, but not every case. This is important because the thesis argument should not claim that every added module is always beneficial. The better claim is that the full retriever improves the overall evidence and answer-quality profile while leaving a smaller set of hard cases for future work.

Runtime

Reranking increases retrieval time, but generation time remains the dominant part of the end-to-end answer path in this diagnostic. The full current retriever is slightly faster than R3_reranker in this run, but this should not be overinterpreted as a stable latency improvement because server load and cache state can affect timing.

Interpretation

This run evaluates the whole retriever-to-answer path while holding the generation model fixed.

The clean conclusion is:

  • R0 to R2 does not show a clear aggregate answer-quality gain.
  • R3 is the first major aggregate improvement.
  • R4 is the best overall condition in this run.
  • The current retriever improves quality and reduces blocking cases, but remaining failures are still concentrated around evidence sufficiency and missing key conditions.
